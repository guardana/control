# ADR-0002: Protobuf contracts, generated code committed

Status: accepted
Date: 2026-09-09

Amended by [ADR-0011](0011-contract-corrections-before-publication.md), which
corrects the frozen contract once more, before it is first published.

## Context

Adapters, SDKs and external policy engines exchange the same messages. Without
one source of truth each side drifts, and a field that carried security meaning
disappears without anyone noticing.

## Decision

Protobuf is the source of truth, under `api/proto/guardana/control/v1/`. Buf
runs lint and breaking-change checks. Generated Go is committed under
`api/gen/go/` so a consumer needs no plugin chain to build.

The `v1` messages are frozen. `schema_version` carries `1.0`, and the change
rules below bind.

Unknown input is refused on both wire paths, provided `pkg/contract` reads the
bytes before the Protobuf runtime does:

- JSON goes through protojson with unknown fields rejected.
- Binary protobuf does not reject on its own. It keeps an unknown field as
  unknown bytes, so `pkg/contract` owns the decode and walks the whole message
  tree, including repeated fields, `oneof` members and well-known types, and
  refuses what it finds.
- **Inside a map entry the runtime discards an unknown field, and a key or
  value sent on a wire type it is not read from, before any walk can see it.**
  Measured: a 21-byte message re-marshals to 19 with no error and nothing on
  any `GetUnknown()`. So `Decode` reads each entry of `Principal.attributes`,
  `Resource.labels` and `RunContext.budgets` before the runtime does. It
  refuses such a field as an unknown field of the map
  ([ADR-0011](0011-contract-corrections-before-publication.md)). A message the
  runtime parsed anywhere else has lost those fields for good.
  `Obligation.params`, in a `Decision`, is a map too. No binary decoder for a
  `Decision` exists yet, and one would need the same pass.

A validator handed an already-parsed message cannot make this claim at all: a
message decoded with `DiscardUnknown: true` is indistinguishable from a clean
one. That is why the decode belongs to `pkg/contract` and not to a caller.

An undeclared enum number is not refused at the boundary either. Neither wire
path detects it, on scalar or repeated fields, so a descriptor lookup finds it
and the decision path turns it into `INDETERMINATE` with a reason code, never a
transport error. That keeps `INDETERMINATE` out of an adapter's error branch,
where invariant 4 would be lost, and it keeps the enum value sets **open**: a
value added in a later minor version degrades for an older receiver instead of
breaking it.

Two rules govern every message:

- **Absence is never more permissive than presence.** A field a producer forgets
  must not read as the permissive answer. A boolean that would grant something
  by being false is written the other way round, and an `UNSPECIFIED` enum value
  is treated as the restrictive case.
- Changing the security meaning of an existing field requires a new package
  version and its own record.

Rules for changing a contract:

- An added field documents its default and what a receiver does when the field
  is **absent**. What a receiver does with an unknown field is stated once,
  above, and is not restated per field.

## Security / compatibility impact

Rejecting unknown fields on the JSON path is deliberate. Silently dropping a
field the producer believed was security-relevant is a false green: the call
gets authorized against less information than the sender thought it sent.
Committing generated code also means a reviewer reads the wire surface in the
diff instead of trusting a generator to have produced what the schema says.

## Alternatives considered

- JSON Schema or OpenAPI as the source. No compiled breaking-change gate, and
  weaker types across languages.
- Generating at build time instead of committing. Every consumer then needs the
  right plugin versions, and the wire surface leaves the diff a reviewer reads.
- Permissive JSON that ignores unknown fields. Easier interoperability, paid for
  with silent loss of security-relevant input.

## Consequences

`api/gen/go/` appears in diffs and has to be regenerated by the pinned tool
versions. A producer on a newer major schema talking to an older receiver is
refused rather than partially understood, which is the intended trade.

Refused does not mean silent. The refusal is a `VERDICT_INDETERMINATE` decision
carrying `UNSUPPORTED_SCHEMA` and an `EVENT_KIND_ACTION_BLOCKED` event, never a
transport error that leaves no record: a block an adapter turns into an error
string loses invariant 4 in that adapter's error branch, and loses the evidence
that the block happened at all. The correlation identifiers are read as opaque
strings for that record, and the decision states that the envelope's security
semantics were not interpreted. Nothing about the message is acted on.

## Validation

Runnable today: `make proto-check` runs `buf lint` and `buf format -d
--exit-code`, then regenerates into a temporary directory and `diff -r`s the
result against `api/gen`. `go test ./internal/contract/` round-trips the
fixtures in `testdata/contracts/action_envelope/` and asserts that an unknown
JSON field is rejected rather than dropped.

`buf breaking --against '.git#branch=main'` compares against the repository's
own history. The commit that froze the contract was a breaking change against
the draft messages, and ADR-0011 records one more set of corrections made
before the contract was first published. From the commit that landed them, a
breaking finding is a failure. The check uses the `FILE` category on purpose:
besides the wire it guards the generated Go's source compatibility, so it also
refuses changes both encodings survive, such as renaming the package.

Written but never run: the `proto-breaking` job in `.github/workflows/ci.yml`,
which compares against the remote's `main`; no workflow has executed, because no
remote repository exists. `make proto-breaking` runs the same comparison against
the local `main`, and prints UNKNOWN and fails, never a pass, in a tree with no
history.
